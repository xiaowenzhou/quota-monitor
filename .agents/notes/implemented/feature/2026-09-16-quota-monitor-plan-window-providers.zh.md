# Agent Note: Plan-window and budget-pool quota providers

Status: implemented

[English](2026-09-16-quota-monitor-plan-window-providers.md) | 中文

## Problem

额度监控原先识别四种余额形态，而这四种回答的是同一个问题：还剩多少钱。操作者可能配置的另外两个提供商回答的却是另一个问题。Cline Pass 计量的是流逝的时间而非货币——它施加一个滚动的 5 小时窗口，外加按日历计的周窗口与月窗口，三者中最紧的一个填满时会话即告停止，与剩余信用无关。AgentRouter 则把一个账户拆分到若干具名预算池上，因此单一的账户剩余额度会掩盖究竟哪个池即将见底。把二者中任何一个折叠进现有的单个 `balance` 数字，恰好会丢掉操作者真正需要的那个事实。

面板同时自带文案。面板组件中的每一条字符串都是中文字面量，这为本仓库"客户端文案归语言词典所有"的规则所禁止；一旦本包的 `src/client` 目录树被发现，`verify-client-ui-i18n` 就会将其拒绝。

## Decision

**账户读取结果可以在其头条数字之外携带拆分明细行。** `QuotaAccountReading` 新增 `planWindows` 与 `budgetPools`；对四种余额形态而言二者均不存在，因此既有行保持不变。头条的 `remaining`、`limit` 与各窗口自己的 `resetAt` 仍是选择器标签与占比条所需的单一数字，因此任何消费方都无需理解新数组即可继续工作。对 Cline Pass，头条报告最紧的那个窗口，因为它是最先让会话停止的那个；对 AgentRouter，头条报告账户剩余额度，当摘要未披露该值时则回退为各池之和。

**Cline Pass 以该路由的 Bearer 凭据读取 `{baseURL}/users/me/plan/usage-limits`。** `type` 的三个取值 `five_hour`、`weekly`、`monthly` 映射到面板能够标注的三行，其余取值一律跳过，而不是以猜测的标签渲染：该端点可能新增某个已发布构建没有对应行的窗口，而标错的窗口比缺失的窗口更糟。百分比在解析器中一次性收敛到 0–100，而不是在每次渲染时收敛，因为网关会报出超过 100 的超用值，也会在退款后报出小于 0 的值，而面板正是直接按该数字绘制占比条。已经过去的 `resetsAt` 时刻会被丢弃，因为指向它的倒计时什么也显示不了。

**AgentRouter 读取 `{origin}/desk/v1/stepcode/user/info`。** 它是唯一从 baseURL 的源（origin）而非 baseURL 本身取址的探测，因为所配置的值指向推理 API，而 desk API 与之并列提供；若某个 baseURL 无法解析为 URL，它便没有可供探测的 desk 源。该端点未随其 `usage_summary` 与 `budget_pool_usages` 数字披露单位，因此这些数字以中性的 `credits` 标注按原值报告，而不是在"该衍生实现沿用了 new-api 的 1/500000 美元单位"这一假设下换算——换算一旦出错就会偏离五个数量级，而且看上去仍然合理。小节内的键名取自有序候选清单，即本文件已用于 Sub2API 面板的那套形态，因此字段改名只会使该行退回手动兜底，而不会报出错误数字。与 Sub2API 读取器不同的是，此处只查顶层：这些小节把自己的数字命名在顶层，而嵌套搜索会让某个无关的内层对象提供该行的头条数字。

两个提供商既可按提供商路由 id 命中，也可按其 baseURL 所指的主机命中，与 DeepSeek 和 MiniMax 既有的命中方式一致，因此经代理域名接入的路由同样能解析。

**面板文案迁入具类型的 `quotaMonitor` 语言命名空间。** `src/client/locales.ts` 持有两种随发行词典，`main` slot 注册声明 `locale: NS`，每个组件都经框架的 `t` 席位读取自己的文案。倒计时的格式化成了其中值得一提的情形：一个拼装出 `重置于 …` 的、返回字符串的格式化函数，正是该门禁所拒绝、也正是另一种语言无法重排语序的写法，因此该辅助函数现在返回倒计时的各个部分，由词典持有整句。

## Verification

`tests/adapters.spec.ts` 钉住两种形态：窗口排序与最紧窗口的信封、`data` 信封、被跳过的未知 `type`、两端的收敛、被丢弃的已过期重置时刻、由"剩余"侧或"总额与已用"侧任一推导出的逐池剩余额度、行内未披露名称时的池编号，以及那些回退到手动额度的拒绝情形。`verify-client-ui-i18n` 在本包的 `src/client` 目录树上通过，这正是"面板文案确实走到了词典"而非"仅仅存在一份词典"的证明。

## Alternatives considered

**把 Cline 的每个窗口报告为独立的提供商行。** 予以否决，因为三个窗口共用一个账户、一份凭据与一个用量计数器；拆分会使 token 统计行变成三倍，并破坏提供商路由与其 `llm/stream` 桶之间的同一性。

**按 new-api 的额度单位换算 AgentRouter 的数字。** 予以否决，因为 AgentRouter 派生自 new-api 并不构成"desk API 沿用了该单位"的证据，而且其失败是无声的：偏离 500000 倍的余额渲染出来仍是一个合理的数字。中性的 `credits` 标注对"端点究竟披露了什么"是诚实的。

**为 AgentRouter 的每个字段钉死一个确切拼写。** 予以否决，因为该端点没有文档；钉死的拼写会把任何改名变成错误或缺失的行，而已用于 Sub2API 的候选清单只会退回手动兜底。

**保留面板的中文字面量并为本包开豁免。** 予以否决，因为该豁免将不得不随本次改动新增的每一行而扩张；而该门禁的价值恰在于：遗漏会在引入它的那一行失败，而不是累积成一个中英混杂的界面。

## Consequences

- 若某网关新增了本构建没有对应行的套餐窗口，该窗口会被静默丢弃，直到有人同时补上一个词典键与一个 `QuotaPlanWindowKind` 成员；仅当它属于三种已识别类型之一时，最紧窗口的头条才会把它计入。
- AgentRouter 的数字彼此之间可比，但与其他行中的货币数字不可比，因为面板以"端点未能披露的那个单位"标注它们。
- 现在为面板新增一行的代价是两条词典条目而非一个字面量，且双语成对性在注册处即被强制。
- 探测文件如今在一次端点遍历之下容纳了六种形态；下一次新增之前，应当在候选键清单开始相互碰撞之前，先掂量把逐提供商的读取器从共享模块中拆分出去。
