# Agent Note: A spend-and-budget quota panel, and asking a gateway what it is

Status: implemented

[English](2026-09-17-quota-monitor-spend-budgets-and-detection.md) | 中文

## Problem

额度面板此前报告 token 与剩余余额，到此为止。运维者真正要问的三件事缺席，第四件则在无声地给出错误答案。

运维者问的是这个月花了多少钱，而不是消耗了多少 token。Token 总量是这个问题的输入，从来不是它的答案：它无法与账单对照、无法按价值在提供商之间切分，也无法与任何人设定的上限相比。

运维者还要问是哪个会话花掉的。折叠缓存本就以会话 id 为键，但报告把这个键丢掉了，只报告按天、按路由的行，因此"一个下午烧掉整月预算的那一次运行"与平稳使用毫无区别。

运维者提出这些问题的场合往往不是这个面板。数字只存在于浏览器视图里，因此要把它们附到缺陷报告、报销单或电子表格里，就得手工重抄一遍。

第四件是给出错误数字而非缺失数字的那件。`new-api` 部署在 `/api/status` 声明自己的配额计价单位；本包却假定了历史上的"每美元 500000 单位"常量。改过单位、或以 CNY 展示的部署，其卡片上的每个数字都差着一个没人会注意到的倍数。另外，`sub2api` 适配器按序遍历一组面板路径，并把找到的任何东西都塞进余额卡片——即便该家族中某些网关的回答其实是计量型订阅。

面板自身的组织方式也有对应的毛病：一次只显示一个提供商的账户选择器，逼着运维者逐个点开才能找到额度耗尽的那个。

## Decision

**价格属于配置。本包不随附价目表。** `pricing.currency` 加 `pricing.rules` 是费率的唯一来源，没有规则时构建出的报告根本不带开销字段，而不是带一个 0。内置表格正是本仓库明令禁止的那种硬编码可调参数：中转会按自己的费率转售同一个模型 id，公开价格会不经通知地变动，而过期表格的失败是无声的——它会在正确数字本该出现的位置渲染出一个自信而错误的数字。想看开销的部署，自己声明它实际支付的价格。

规则按其给出的最窄名字匹配 `provider · model` 路由：提供商加精确模型（4+2）、提供商加以 `*` 结尾的系列（4+1）、按提供商（4）、仅模型的各变体，最后是全量兜底（0）。同级相持时取 `from` 不晚于被定价那天的最近一条，因此新增规则只对当天及以后生效，历史仍留在当时生效的规则上。开销按每天各自的计数推算，而非依赖流水累计值，这正是按天、按会话、按月与累计四个数字彼此一致的原因。

**部分定价的总量要披露，而不是扣下。** 每份开销视图都带 `amount` 与 `unpricedCalls`。本次改造所参考的实现把任何无法完整定价的数字藏在破折号之后；那等于连它已经知道的那部分也一并扣下，使运维者无从下手。写出"$4.12，37 次调用未定价"同时告诉了他们下界与缺口的大小。

**预算以推算开销来衡量，没有价格的预算在加载时失败。** `budgets.daily` 与 `budgets.monthly` 以 `pricing.currency` 计价。当预算存在而价格规则为零条、或 `criticalPercent` 低于 `warningPercent` 时，`assertConsistent` 在构造函数中抛错。只可能永远报告 `unknown` 的预算是配置错误，而本仓库的规则是：误配置在加载时响亮失败，而不是渲染成一种状态。至于开销全部落在无法定价的调用上的窗口，它仍报告 `unknown` 而不是让人安心的 0%，因为那种组合是数据，不是误配置。

**报告按 id、活跃时刻与路由列出会话——绝不按标题。** `SessionFoldState` 新增 `lastActiveAt`，`buildUsageReport` 为每个会话发出一行，含 token、调用次数、路由与开销。它不带对话标题：标题是由提示词衍生的文本，而 `quota_usage` 存储域所记载的内容只有计数与路由 id。为了让面板少查一次而把该缓存扩张到存放标题，等于把提示词文本放进一个记账存储。

`buildUsageReport(states, options)` 同时把四个位置参数改成一个选项对象，因为新增的 `prices` 与 `budgets` 都是可选的，而第五、第六个位置参数会让每一处调用点都变得无法阅读。

**导出走 Remote 面，而不是新开 HTTP 路由。** `exportUsage(request)` 返回 `QuotaExportDocument`——文件名、媒体类型与内容——由浏览器经 Blob 保存。新开一条回环路由，需要自己的授权方案、自己的生命周期与自己的接口面，而这个操作面板本可以经它已有的连接直接请求。JSON 文档携带用量报告，外加每条受监控路由一行、写明其适配器与状态；余额、方案窗口与凭据引用不在其中，因为导出文件是会被附到缺陷报告上的东西。

两份 CSV 都为每个单元格加引号、在 UTF-8 BOM 之后以 CRLF 分行，并给以 `=`、`+`、`-`、`@` 开头的文本单元格加上单引号前缀。`provider · model` 路由 id 恰好是电子表格公式注入所需的那种可被外部影响的值，而这道防护只花一个正则表达式。

**`new-api` 部署会被询问它如何计价配额。** `/api/status` 与用量读取并发发出；`quota_per_unit` 覆盖历史常量，`quota_display_type: CNY` 会套用该部署自己的 `usd_exchange_rate`，其他展示单位一律报告 `unsupported` 而不是改标签。500000 这个历史常量只作为"不提供状态路由的部署"的回退存在——那是关于旧版构建的协议事实，不是可调参数。

**Sub2API 的读取结果自述其形态。** `QuotaAccountReading` 新增 `mode`，`readSub2apiUsage` 从回答本身判定是钱包、总配额，还是按周期的订阅上限。同一个网关家族确实在同一套协议下提供全部三种，因此适配器 id 无法决定卡片的形态；`isValid: false` 或 `is_active: false` 报告为 `unauthorized`，而不是空钱包。

**不认识的网关会被反问一次，且不携带凭据。** `detectSub2apiPanel` 以 `auth: 'none'` 探测 `GET {origin}/api/v1/settings/public`，只接受 `code === 0` 且 `data.affiliate_enabled` 为布尔值的回答。它仅在没有任何规则解析出适配器、且事后确实有凭据可用时运行，其 promise 按提供商与 base URL 缓存，因此刷新循环无法把它变成反复的流量。`detection.enabled`（默认为真）让希望对未知主机零无人值守请求的部署关掉它。

**面板先一次呈现全部账户，再展开其中一个。** 一列标签构成选择器，每个提供商一枚状态圆点，因此额度耗尽的账户不必被选中也能看见。其下卡片以主数字（剩余、已用、上限）开头，接着是方案窗口，然后是预算池；再往下是带推算开销的三块总量卡、预算进度条、当月按星期对齐且每格带 token 数的日历、所选那天的路由、最活跃的会话，以及导出行。着色梯度是对 `--dsw-alias-state-business-primary` 做五级 `color-mix`，而不是另起一套调色板，因此日历会随主题切换。

## Verification

`tests/pricing.spec.ts` 钉住每一级具名程度上的规则选择、`from` 边界的两侧、缓存分桶回退到输入费率，以及没有价目表时累加器什么都不报告。`tests/usage-fold.spec.ts` 钉住会话行及其排序、零 token 会话不出现在列表里但仍被计数、按行/按天/按会话/按窗口的开销、被披露的未定价次数，以及包含 `unknown` 在内的每种预算状态。`tests/export.spec.ts` 钉住 BOM、CRLF 分行、加引号的单元格、针对恶意路由 id 的公式防护、未定价报告中留空的开销列，以及 JSON 文档不得包含的字段。`tests/config.spec.ts` 钉住随附价目表为空以及 `assertConsistent` 的两种拒绝，其中一种经真实的 `ctx.plugin` 加载。`tests/detection.spec.ts` 在一条带真实设置档案与凭据引用的真实可配置路由上启动服务，钉住探测不携带 `authorization` 头、两次读取之间只探测一次、关闭时完全不探测，以及卡片由读取结果自述的形态而非适配器 id 决定。`tests/adapters.spec.ts` 钉住 `new-api` 的计价单位读取与三种 Sub2API 回答形态。

## Alternatives considered

**为知名提供商随附内置价目表。** 作为带无声失败模式的硬编码可调参数被否决。模型价格会在本包不发版的情况下变动，中转以不同费率转售同一个模型 id，而错误费率会在正确数字本该出现的位置给出一个合理的数字。配置让部署声明它实际支付的价格，而未配置的部署看到的是 token，不是虚构。

**只要总量里含有未定价的调用就整块隐藏。** 否决：那会丢掉已知的那部分。参考实现正是这么做的，结果是运维者期待金额的位置出现一个破折号，而且无从判断缺口是一次调用还是一万次。金额加未定价次数严格地信息更多，误导性并不更大。

**为未定价的路由按相似模型估一个价。** 否决，因为猜出来的费率一旦进了预算进度条，就与配置出来的费率无法区分。未定价的调用会被计数并如实命名。

**把对话标题存进折叠缓存，好让会话列表能显示它。** 否决，因为 `quota_usage` 存储域所记载的内容就是计数与路由 id，而标题是由提示词衍生的文本。列表以 id、最后活跃时刻与路由标识会话；这个缺口记在"已知限制"中，而不是用"往记账存储里塞提示词文本"来换。

**像参考项目那样，用新的回环 HTTP 路由提供导出。** 否决，因为 Remote 面本就承载着对这份数据的、经认证且受生命周期管理的访问。第二条传输需要自己的授权、自己的释放与自己的接口面，却不带来第一条所缺的任何能力。

**探测若干候选路径来识别未知网关。** 否决，因为每多一条路径就是又一次对运维者从未指名的主机发出的、不带凭据的无人值守请求，而真正能区分这一面板家族的就是那一个公开设置文档。隐藏该文档的网关继续使用 `monitors.<id>.adapter`。

**保留旧的多路径 `sub2api` 遍历，并把每种回答都塞进余额卡片。** 否决：该遍历会为按周期计量的网关报告一个钱包，那是错误的卡片而不是缺失的卡片。从回答里读取形态，正是协议本就披露的东西。

## Consequences

- 不配置价格的部署看到的与此前完全一致：token、余额与窗口，任何位置都没有开销列。开销是可选启用的，其完整程度由部署自己负责。
- 一条价格规则的每个分桶只表达一个固定的每百万费率，因此阶梯价、批量价与按上下文长度计价都无法表达。采用这类方案的部署得到的是下界，不是账单。
- `buildUsageReport` 的签名从位置参数改为选项对象；本包内每处调用点同步迁移，且该函数并未从本包的公开入口导出。
- `usageDomainSpec` 升至 `version: 2` 并带 `compatibleVersions: [1]`，因为版本 1 的记录没有 `lastActiveAt`。这类会话会以活跃时刻为 0 出现在列表中，直到其日志被重新折叠。
- 网关识别为每个不认识的提供商在每个进程内增加一次不带凭据的请求，此后走缓存。认为这不可接受的部署设置 `detection.enabled: false` 并显式指定适配器。
- 提供 `/api/status` 且展示单位既非 USD 也非 CNY 的 `new-api` 部署，现在报告 `unsupported`，而此前报告一个错误数字。这正是有意的取舍：缺失的卡片胜过标错的卡片。
- 面板从四个区块增加到六个。日历按所显示月份自身的峰值着色而非绝对刻度，因此两个月之间无法凭颜色比较；绝对数字在格子标签与导出文件里。
